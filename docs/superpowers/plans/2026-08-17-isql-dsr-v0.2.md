# ISQL-DSR v0.2 Topology, Fusion, and Core SEM/STATE Bridge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Extend ISQL-DSR from replayable finite-active semantic state to a topology-aware, uncertainty-aware multi-proposal runtime with genuinely Core-parseable SEM/R2 and STATE/R2 numeric wire envelopes.

**Architecture:** Preserve v0.1 identity/history invariants while bumping the state/event schemas to v0.2. Topology descriptors are bound to a canonical relation-basis hash and are invalidated whenever relations change. Multi-source semantic proposals are fused deterministically through explicit source weights and axis uncertainty, and fusion is recorded as a replayable event. Core bridging serializes canonical SEM and STATE snapshots as UTF-8 bytes encoded into fixed-width decimal triplets so the resulting wires satisfy ISQL Core v0.4's digits-only payload grammar.

**Tech Stack:** Python 3.11+, stdlib dataclasses/json/hashlib/argparse/unittest/setuptools; no runtime dependencies.

## Global Constraints

- Do not modify the existing `/mnt/data/ISQL_DSR_Runtime_v0.1.0` release.
- Runtime must remain dependency-free.
- Registry IDs are references, never meaning.
- Full DSR semantic state must remain losslessly reconstructible from the STATE bridge.
- Every state-changing operation must remain fail-closed on base revision and previous state hash.
- Topology descriptors must declare the exact relation-basis hash from which they were computed.
- Relation changes must invalidate prior topology descriptors.
- Fusion must be deterministic under proposal input reordering.
- Core bridge payloads must be ASCII digits only and parseable under the Core v0.4 `ISQL<version>:<DOMAIN>:R<0-4>:<CONTROL><digits>` grammar.
- Canonical source artifacts remain UTF-8 with no unicode-escape round trip.
