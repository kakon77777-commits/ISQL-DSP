# ISQL DSR v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build a standalone Python 3.11 ISQL Dynamic Spectrum Runtime v0.1 that represents finite-active semantic spectra, typed relations, context, replayable state transitions, canonical serialization, semantic diff, and a non-lossy Core transport envelope.

**Architecture:** `isql_dsr` is a parallel package, not a modification of `isql_core`. Immutable dataclasses model semantic values and state; canonical JSON is the source of deterministic hashes and exact round-trip; transition events are pure transformations so history can be replayed. The Core bridge exports a versioned STATE envelope without pretending the v0.4 Core spectral registry is the DSR meaning layer.

**Tech Stack:** Python >=3.11, standard library only, `unittest`, `dataclasses`, `json`, `hashlib`, `argparse`, `setuptools`.

## Global Constraints

- Keep ISQL Core Runtime v0.4 unchanged.
- Any runtime state is finite; extensibility is unbounded across revisions.
- Registry/reference identifiers are not equal to semantic meaning.
- Canonical serialization must be UTF-8 JSON with deterministic key ordering and separators.
- Exact round-trip for the canonical DSR object is required.
- AI/model output is a proposal; the runtime itself must be deterministic and model-independent.
- No external runtime dependency is required for v0.1.
