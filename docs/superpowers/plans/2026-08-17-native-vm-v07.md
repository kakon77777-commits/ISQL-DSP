# ISQL-DSR v0.7 Native VM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend v0.6 `.isqlp` programs into a guarded, capability-aware AI-native VM with synchronous subprogram calls and atomic transactions across multiple registered states.

**Architecture:** Preserve v0.6 program/event/state artifacts and add a v0.7 VM program codec in `vm.py`, still using `.isqlp` as the program artifact family. A VM program binds one or more numeric state slots, executes guarded instructions in causal DAG order, checks an explicit capability mask, supports synchronous CALL/RETURN to dynamically-bound single-state subprograms, and publishes no partial state if any instruction, guard, capability, or subcall fails.

**Tech Stack:** Python 3.11+, stdlib only, unittest, existing ISQL-DSR native codecs/registry/state/event machinery.

## Global Constraints

- Canonical artifacts remain machine-native binary; JSON/text are inspection only.
- No human-readable schema labels are required in `.isqlp` canonical bytes.
- v0.6 artifacts and APIs remain valid.
- Registry is append-only and namespace-sensitive.
- State, event, branch, and program hashes remain SHA-256 over canonical bytes.
- Core transport remains `EXEC/R4`, with control field identifying payload family.
- All state updates are atomic at transaction publish boundary.
